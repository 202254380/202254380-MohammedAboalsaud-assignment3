# Requirement and rubric map

This table maps the implementation to the requirements. It is not a promised grade.

| Requirement / criterion | Evidence in this project |
| --- | --- |
| Clear repository structure | Root HTML/README; separate CSS, JS, images, docs, tests, and tools; .gitignore; real local Git commits |
| External API | Live GitHub public repositories; errors, retry, timeout, data checks, labelled cache |
| Complex logic | Combined project search/filter/level/sort; repository controls; field validation; clock-based timer |
| State management | Saved theme, visitor name, project choices, timer, workouts, and tasks; validated reads and memory fallback |
| Functionality (10) | Working browser demos and new features; automated logic and browser checks |
| Code quality (10) | Pure rules in `core.js`; named UI functions in `script.js`; comments explain key decisions |
| Performance (10) | Small optimized portrait, SVG previews, no runtime libraries/fonts, deferred scripts, debounced search, cached API; documented audit attempt and local Lighthouse procedure |
| Compatibility (10) | Relative paths, responsive layouts, keyboard controls, native dialogs; tested widths and explicit browser limits in the test report |
| README quality (10) | Project purpose, feature table, file map, setup, verification, AI summary, and submission links |
| Setup instructions (10) | Python local server, Windows/macOS alternatives, no npm requirement, exact repository root layout |
| Technical details (10) | Architecture, main functions, rules, API/cache states, storage keys, limits, and references |
| User experience (10) | Labelled controls, empty/loading/error states, retry/reset actions, conditional guidance, and honest demo status |
| Effective AI use (5) | Declared work on implementation, debugging, tests, and documentation |
| AI documentation (5) | Usage log, actual intermediate artifacts, final version, declaration; student must add full conversation export |
| AI understanding (5) | Code explanation and review tasks; student understanding still requires personal demonstration |
| Innovation (5) | A portfolio-specific live repository explorer with safe stale-data recovery, combined rules, and a deadline-based study tool |

Before submission, the student must complete the review and evidence requirements in [the checklist](submission-checklist.md).
